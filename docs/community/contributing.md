# Contributing

The source contribution process is documented in [CONTRIBUTING.md](../../CONTRIBUTING.md). See [SECURITY.md](../../SECURITY.md) for private vulnerability reporting. Application-owned Community source is licensed under [Apache-2.0](../../LICENSE); contribute only material you are entitled to share.

The candidate includes reproducible-bug and practitioner-workflow issue forms, a pull-request template and an [Ideas discussion form](../../.github/DISCUSSION_TEMPLATE/ideas.yml). Use the discussion form for a proposed workflow, deployment question or extension design; include a synthetic example, source version and a clear way to judge the outcome. Keep client information and vulnerability details out of discussion posts.

The form is prepared for a future `Ideas` category, whose slug is `ideas`. GitHub requires the form filename to match its category slug. Enabling Discussions or creating a category is a separate maintainer action after publication approval; adding this file does not enable or publish a forum. See GitHub's [discussion category form instructions](https://docs.github.com/en/discussions/managing-discussions-for-your-community/creating-discussion-category-forms).
