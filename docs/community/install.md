# Install, retain and restore your data

The Node installation is the baseline. It needs Node 24.22.1+, npm and enough private disk space for original documents and backups. Linux is exercised locally; the same Node entry point is usable on Windows and macOS, but those operating systems require separate acceptance before an OS-specific support claim. In PowerShell, pass a full quoted path such as `npm start -- --data "C:\Private\ESIA"`. On macOS use a directory within your own account. Choose a new directory outside the application checkout.

Run `npm ci --omit=dev --omit=optional --ignore-scripts`, then `npm start -- --data /absolute/private/path`. Installation fetches pinned npm dependencies unless already cached. Manual operation after installation does not require internet. Build and runtime package files are separate from data; upgrade by replacing the application directory while keeping the explicit private data path. The supported local address is `http://127.0.0.1:4173`; use `--port 4174` to choose another port.

Before handling client information, restrict the data directory to its operating-system owner, enable device/disk encryption and choose an encrypted backup destination. Do not place the data directory in a web root or source-control repository. Local accounts are custody partitions inside the same trusted computer owner, not mutually isolated logins. TCP loopback does not authenticate other local OS users. Separate practitioners who do not trust each other need the authenticated service or separate devices/VMs with independent storage and network boundaries; separate file ownership on a shared host is insufficient.

The minimal package supports text/HTML/Office evidence and manual review; some previews depend on optional device tools. Poppler (`pdfinfo`, `pdftotext`, `pdftoppm`) enables PDF inspection. Tesseract with English data enables explicit OCR; inspect the original page before confirming a citation. GDAL adds selected spatial conversions. Native template analysis requires Python3, lxml, pypdf and Pillow; Office rendering additionally requires LibreOffice, Poppler and fontconfig. Inspect runtime capabilities in Template Studio before relying on any native conversion. No queue worker runs while idle.

Use the project export control for a portable project package. Managed originals, exact source hashes, assessments, action history, issued reports and scoped engagements travel together within package limits. Restore into a fresh installation using **Restore the package's owning account**, then verify an original and an issued report. Registered paths are references to external bytes; resolve them deliberately to matching hashes or retain managed copies before exporting. A project package is not a full-disk backup. Resource-library and lifecycle records have their own explicit export/restore controls; preserve them when those modules are used.

For a complete installation backup, stop the application cleanly, copy the entire private data directory to encrypted storage, record the application manifest and Node version, then restart. A stopped copy includes SQLite and objects consistently; copying a live SQLite file alone is insufficient. Test recovery in a fresh directory before retiring the prior copy. Keep the old application package and stopped data backup until you have checked the upgrade. Restore both together for rollback; never silently drop a schema/package version unsupported by the old reader.

`npm run test:installation` checks manifest hashes and performs a synthetic HTTP workflow with fresh restore and cross-account denial. `npm test` checks manual assessment, immutable history, financing and report adapters. These automated checks establish implementation behavior; they do not establish a practitioner's professional acceptance, document rights or independent security assurance.
