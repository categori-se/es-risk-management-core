# Extension and data interfaces

The community package retains the professional domain model and source interfaces. Extend domain behavior independently of hosting, billing and provider operations. The local browser uses the same-origin `/api/projects`, `/api/engagements`, `/api/project-lifecycle` and explicit exchange/report routes. Those routes validate account custody, expected revisions, exact source references and command shapes; bypassing them to write SQLite or object files breaks the integrity contract.

See [architecture and data flows](architecture.md) for module authorities and processing paths, and [security boundaries](security.md) for local, authenticated and customer-deployment responsibilities. These descriptions travel with the source candidate; they do not imply an accepted customer deployment.

JSON Schemas in `schemas/`, lifecycle TypeScript declarations in `types/project-lifecycle.d.ts`, and `docs/lifecycle-architecture/openapi.json` describe the portable interfaces. The OpenAPI document distinguishes implemented local routes from proposed hosted adapters. Preserve durable IDs, hashes, approved snapshots and original author/provenance records during exchange. Do not treat a shared project identity, common practitioner, source hash or canonical name as permission to reuse another client's information.

`server/engagement-assistance.mjs` provides optional loopback inference and exact-passage indexing; `server/es-ai-providers.mjs` exposes compatible provider adapters. AI routing remains explicit, with current source and task permissions checked before processing. Provider output stays draft until reviewed through the existing workflow. The generated community profile has no private AWS profile/account binding, hosted Cognito client or default external AI credential. Supply a separately reviewed adapter/configuration for your own infrastructure, rather than changing core project records or copying a commercial tenant's settings.

Template bindings and reporting use the canonical assessment data; generated outputs are representations, not replacement findings or new evidence authorities. Institution names do not establish compliance. New institutional formats need field-level mapping and validation against a permitted source version. The package starts with an empty resource catalog so each installation can register its own authorized references and originals. Built-in framework metadata remains identified by edition and current applicability decisions.

The source manifest records profile transformations separately from original file hashes. Any new runtime or UI entry point must join the local routing/import closure and pass the independent installed check. Security fixes, basic authorization, auditability and project export remain part of the core; they must not become paid prerequisites for handling confidential data safely.
