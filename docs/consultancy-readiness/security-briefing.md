# Technical security briefing for a scoped assignment

Complete this briefing with the client/deployment owner against the exact selected profile, source/artifact and secret-free configuration hashes. Retain recipient, presenter, date, questions, corrections, evidence references and the owner's separate decision in `technical_briefing` of the private [operations packet](client-operations.json). This document is a briefing script; no briefing or client acceptance is claimed.

| Explain and demonstrate | Evidence or decision to retain |
| --- | --- |
| Who runs and controls the application? | Local single trusted computer owner vs authenticated hosted/customer service; operator/admin powers, device/network/storage custody and exact deployment. Other users on one host can reach loopback; OS file ownership does not isolate HTTP. |
| Where does information go? | Original → immutable version/hash → extraction/index → reviewed evidence/finding → approved baseline → issued artifact/export. AI is a separately permitted optional path; external references are not retained originals. |
| What separates clients? | Account/project/engagement and current exact grants, including two clients on the same physical project. Same names, email addresses, hashes or reviewer participation confer no sharing right. Show sanitized cross-client denial in the actual profile. |
| What protects stakeholders? | Neutral summary, encrypted identity/location/investigation groups, explicit case/source grants and separate passphrase custody. Test unauthorized originals, current/history fields and export; explain masking and indirect-identification limitations. |
| Can search or AI read protected data? | Read rights and AI-processing rights are different. Recheck exact current originals, passage restrictions and case policy for lexical/semantic/hybrid search, model context/history and exports. Revocation after selection must suppress dispatch/disclosure. Source restrictions cannot be downgraded by passage labels. |
| Is AI enabled and evaluated? | Disabled unless the exact route/model/processing purpose, source permissions, retention, credentials, evaluation, price/budget and stop conditions are approved. Model drafts require human review; simulations and valid JSON do not establish professional accuracy. No automatic paid fallback. |
| Who may approve and change work? | Actual authenticated roles for shared work; local names are declarations. Exact baseline, source/citation hashes, immutable issued outputs, correction history and separate client acceptance. |
| Who holds keys? | Device/volume/backup key owner, protected recovery reference, AI vault master-key/credential rotation or re-entry, case passphrase limits. Never include secret values in project packages, briefing notes, logs or Git. Losing an unrecoverable case passphrase cannot be fixed by a report export. |
| What survives an outage? | Consistent encrypted backup, separate key custody, actual destination restore, measured recovery time/loss, exact originals/outputs/history and rollback target. The application does not establish the operator's backup cadence. |
| What happens at exit or incident? | Current grant/provider/token revocation, in-flight work/remote retention and downloaded-byte limits; complete editable handover and destination restore; deletion/legal hold/backups expiry; named incident authority and contact. |
| What remains unaccepted? | Actual deployment JWT/IAM/network/encryption, independent security review/findings, model/content accuracy, real practitioner usability and client/contractual acceptance as applicable. Public source/licence and signing authority remain separate decisions. |

Use the [architecture](../community/architecture.md), [security boundaries](../community/security.md), [authenticated acceptance](../community/authenticated-profile.md) and [onboarding/key-custody checklist](client-onboarding.md) for implementation detail. The deployment's private threat model and exact retained release evidence inform the operator's review; do not publish private evidence or infer that an automated security threshold certifies the client deployment.

End by recording the questions the client could not answer, evidence still missing, responsible owner and the separately agreed next decision. Do not turn attendance, a checklist's structural completeness or a synthetic browser pass into security or professional approval.
