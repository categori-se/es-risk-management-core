# Observe the practitioner workflow

This protocol prepares a consented observation; it reports no completed independent study. The earlier independent IFC PS5 qualification review stays on hold at the owner's request. Its professional qualification packet and decisions remain separate from usability observations.

Use the selected private engagement and authorized evidence. A low-sensitivity or synthetic rehearsal can prepare the study. Do not copy client documents, participant identities, protected stakeholder details or recordings into Git, public issues or this template. An observer reference can identify a privately held consent/participant record without exposing the person's name. Agree observation/recording permissions, retention and deletion first.

## Before observing

Record the exact running source commit/artifact, device/OS, deployment profile, mandate, governing requirement editions, source permissions and task acceptance criteria. Select a practitioner unfamiliar with the app when evaluating first-use success. Record their relevant experience privately. Use an independent observer for an actual observed session; a self-rehearsal remains a synthetic rehearsal in this instrument. The local role picker identifies a declared recorder and does not authenticate that participant or observer.

In the existing engagement open **Evidence → Measure assignment effort and verify handover → Observe the ten practitioner tasks**. The saved record uses the same account/project/engagement pilot repository, pins the current dataset/criteria/protocol and does not change canonical findings, reports or approvals. Start the observation before work, keep task notes privately, then reopen the current measurement context after the work to save the final dataset pins. If the engagement changes after opening the form, refresh before submitting; a stale dataset is rejected. Retain the starting dataset/artifact references in the task evidence notes so the before/after study can be reproduced.

| Create engagement | Correct account/project, mandate, reporting period and assigned role references. |

## Capture without coaching away failures

For every task select completed, assisted, failed or not attempted. Record observed active seconds, waiting seconds, correction seconds, assistance seconds and substantive correction count. Correction and assistance seconds are included in active time; never add them twice. Tasks are sequential and active plus wait time cannot exceed the session. Record interruptions and setup separately in private notes. A task not attempted has zero measured work and an explicit reason.

Retain an evidence reference and qualitative feedback for every task. For a failure capture the visible symptom, impact, sanitized reproduction and private evidence reference. Add the retest reference after a fix, preserving the original observation. Record assistance even when it succeeds; do not quietly mark that task unassisted. Ask what was confusing, which source or approval was hard to trust and what they would change first. Save overall feedback and the highest-priority correction.

The form is foreground-only, creates no recording or telemetry and sends no invitations. The API accepts bounded detailed failure lists at the existing `pilot-evidence/task-observation` route; the form captures one consolidated failure description per task. An actual observation needs distinct participant/observer references and a consent reference. These remain declarations; the application does not verify identity, credentials, consent validity or the evidence content.

The retained observation explicitly grants **no professional approval or independent practitioner acceptance**. Existing six-phase app/Word–Excel measurements remain the comparison authority: use the same dataset and acceptance criteria, count all preparation/correction/review/output/handover work and obtain actual independent work-product review before reporting savings. Ten-task observations do not automatically create those accepted measurements.

## Retrospective and later monitoring

For the retrospective choose one completed case whose ToR, original documents and professional deliverables may lawfully be used. Freeze the original comparison outputs before running the app. Have the responsible independent professional examine the complete finding denominator, omissions, unsupported/fabricated conclusions, citation accuracy and output usability; retain disagreements and all correction effort. Reference that result in the existing qualification/work-product review rather than making a usability pass stand for professional accuracy.

For longitudinal acceptance return to an actual later reporting period and record the elapsed period, new site/monitoring originals, action changes, verification decisions, practitioner/client feedback and a fresh restore. The synthetic consultancy demonstration proves workflow mechanics only; see the [profile boundaries](../community/architecture.md). The [operations packet](client-operations.json) keeps retrospective/longitudinal evidence pending until real references exist. Do not reopen the deferred PS5 nomination question to prepare these instruments.
