# Contributing to E&S Risk Management Core

Application-owned Community source is licensed under Apache-2.0. Read `LICENSE`, `NOTICE` and the source manifest before contributing. Private development history, client material and operational configuration are excluded from this repository; the application licence does not grant rights to them.

Use Node 24.22.1+. Run `npm ci`, then `npm test` and the relevant installed acceptance command. Develop and exercise browser journeys locally with synthetic data and protected APIs blocked. The generated community package has `npm run test:installation` and a documented Linux container check. Preserve data/schema compatibility, exact evidence references and approved assessment history; describe migrations and rollback behavior when changing storage.

Open an issue describing the professional workflow, expected behavior and a small synthetic reproduction. Keep changes focused on that outcome. A pull request should explain the final behavior, tests, data/security implications and any deliberate limitation. Human professional judgment and independent security acceptance cannot be replaced by an automated assertion.

Submit only material you have the right to contribute. Identify third-party sources and applicable licenses, preserve notices and explicitly label synthetic fixtures. Do not submit confidential client/employer documents, credentials, production account identifiers or proprietary institutional content. Do not email or contact third parties through automation on a contributor's behalf.

Security fixes, basic access control, audit records and portable project export belong in the community core. Commercial extensions should use stable interfaces and preserve the same canonical project/evidence records. Follow the existing shared workspace, identity and evidence contracts instead of introducing duplicate authorities. Cross-client information sharing always needs an explicit, currently authorized boundary crossing.

See `SECURITY.md` for private vulnerability reporting. Use the repository's available issue and discussion tools for contribution feedback. Independent practitioner acceptance and confidential deployment approval require their own evidence.
